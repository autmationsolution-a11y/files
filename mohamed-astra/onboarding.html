Onboarding request

The inputs that bring Astra live. Most are quick. The only data needed is one small sanitized sample, shared privately.

No data on GitHub. Real observatory data is never uploaded here. Share the sample file by a private channel only.

A Data

A1. Sample file one Campbell .dat / TOA5 export, 1-2 weeks, with header lines. Private, not committed.
A2. Sensor inventory list of instruments.
A3. Depths e.g. 10, 30, 50, 100 cm.
A4. Variables each variable with its exact column name.
A5. Units per variable. Matric potential: kPa / hPa / pF.
A6. Sites / stations station identifiers.
A7. Frequency + timezone sampling step and timestamp timezone.
A8. Physical limits hard min/max per variable (for Layer 1 checks).
A9. Existing flags any quality-flag convention already in use.

B Environment

B1. Go-live machine + OS
B2. Python 3.10+ and permission to install duckdb / pandas / pyarrow.
B3. Where it runs CNRS machine, or Younes's machine on a copied sample.
B4. Data location where the files live on disk.

C Brain

C1. Local model governance likely requires it. Confirm.
C2. Local engine Ollama / llama.cpp / LM Studio / vLLM / MLX.
C3. Hardware GPU + VRAM, or CPU + RAM. Decides model size.
C4. Emmy (optional) Mistral/Emmy for non-sensitive text only, if permitted.
C5. Default model preferred model id.

D Interface

D1. HUD hosting at 127.0.0.1:8000, or a separate host.
D2. Voice on / off (off recommended for v1).
D3. Language FR / EN / bilingual.

E Repository & governance

E1. Host GitHub, or mirror to a CNRS GitLab / forge.
E2. Owner / admin
E3. Data boundary confirm data never leaves the machine (assumed yes).
E4. Requirements FAIR, reproducibility, licensing rules.

F Roles

F1. Data owner
F2. Threshold sign-off who validates Layer 1 limits and QC thresholds.
F3. Decision rights Mohamed vs Younes.
F4. Day-one user
Go-live gate: once A1-A8, B1-B3 and C1-C3 are answered, Astra can go live. The rest can follow.
